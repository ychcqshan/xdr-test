## 🛠️ 生产环境部署黄金军规与故障排查

### 1. 核心设计原则

1. **容器隔离与服务名寻址**：微服务在 Docker 中运行时，严禁使用 `localhost` 作为内部服务通信的地址，必须使用 `docker-compose` 中的服务名（如 `http://auth-service:8001`），依靠 Docker 内部 DNS 解析。
2. **跨域代理路由**：前端统一通过 Nginx 80 端口使用相对路径 `/api/v1` 发起请求，由宿主机 Nginx 代理分发给网关的 `127.0.0.1:8000`。严禁前端直连 `http://IP:8000`，规避云服务防火墙非标端口拦截的问题。
3. **Redis 通用连接配置**：凡是引入 Redis 依赖的微服务（`gateway`、`auth`、`asset`、`baseline`、`threat`），在 `docker-compose.yml` 中必须显式配置环境变量 `- SPRING_DATA_REDIS_HOST=xdr-redis`。
4. **LF 换行符敏感**：后端 `.yml` 配置文件一律采用 UNIX 格式（`LF`），防止 Windows `CRLF` 破坏 YAML 的缩进和列表结构。

### 2. 闭环排查指令
- **网关 502/连接错误**：
  ```bash
  docker logs -f api-gateway
  ```
- **强制容器更新**：
  ```bash
  # 若 docker-compose 指令报 "No containers to restart"，直接使用底层 Docker 重启：
  docker restart api-gateway
  # 或者强行重新编译加载：
  docker-compose up -d --build api-gateway
  ```
